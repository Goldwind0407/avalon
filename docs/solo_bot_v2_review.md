# 單人 BOT V2：規格與目前程式的差異檢查

日期：2026-11-12。程式基準：`feature/solo-bots` 的 `7dec14a`。

此為實作前的差異基準；後續資料格式、權限與首批策略／台詞的實作進度，請看 [實作契約](solo_bot_data_contract.md) 和更新後的 [目前規則](solo_bot_rules.md)。

本次工作為規格檢查，沒有套用新策略或台詞。下文將「目前已具備」「需要新增」與「規格需要釐清」分開列出。

## 結論

**V2 方向可行，可以沿用現有裁判、桌面、動畫、私人資訊投遞與暫停流程。**

新增的 JSON 是台詞與條件規格資料，不能直接取代現有 `speech()`。需要條件映射、事件資料、台詞挑選與渲染層，才能讓這些台詞有正確的觸發依據。

## 2. 接入前要先對齊的規格

### A. 宣稱政策名稱不一致

台詞文件的 `ClaimPolicy` 示意列出五種政策；JSON 實際出現六種。

`G07` 使用 `intentional_opinion_bluff`，與其他規則的 `strategic_opinion_bluff` 不同，示意 enum 也沒有對應的額外成員。

接入前應明確決定兩者是否同義。無法識別的政策不能默認放行，也不能悄悄當成一般公開事實。

### B. 角色 ID 與目前 Dart enum 不同

| 台詞庫 | 目前程式 | 接法 |
|---|---|---|
| `loyal_servant` | `Role.loyal` | 明確映射 |
| `evil_minion` | `Role.minion` | 明確映射 |
| `lancelot_good` | 初始角色可能是 `Role.lancelotGood` 或 `Role.lancelotEvil` | 依**目前陣營**選台詞 |
| `lancelot_evil` | 同上 | 不能只依初始 enum 名稱選台詞 |
| 其他角色 | 名稱可對應 | 仍建議透過統一轉換函式 |

若直接把 enum 名稱轉成台詞角色，蘭斯洛特換邊後會使用錯誤的台詞集合。

### C. 高階意圖與情境群組的粒度不同

V2 功能規格要求至少 15 個高頻意圖、每個至少 3 句。JSON 則是 105 種不同 `intent`，每種 2 句。

建議將「支持、反對、質疑投票、為自己辯護」等作為少量高階意圖，105 組保留為情境／規則 ID，再核對每個高階意圖的可用台詞數量。否則原樣一對一映射時，不符合每意圖至少 3 句的驗收文字。

### D. `XSW04` 遺漏「出牌者知道自己的原始牌」

台詞「只有使用劍的人知道原始牌」說得過滿。出牌者本來就知道自己交的是哪張牌；持劍者額外知道的是被翻轉的那張原始牌。

目前條件只有 `claimantNotSwordHolder`，因此可能錯誤質疑合法的本人出牌宣稱。應排除「宣稱者就是該張牌的出牌者」，也要區分轉述、推測與自稱親眼查驗。

### E. `XSW03` 不應只憑原始成功牌就說改變了遠征結果

看見原本是成功、並將它翻成失敗，確實改變了牌面與失敗張數；**不一定改變遠征成功／失敗的判定**。

例如需要兩張失敗的遠征，原本沒有失敗牌，翻出一張後仍然成功。

建議將台詞改為「改變了最後的牌數」，或增加「翻牌前後遠征勝敗確實不同」的條件，才使用「改變了結果」的說法。

### F. `G16` 等投票矛盾台詞必須標明資料時間

現在流程是：組隊 → 討論 → 投票 → 全員完成後公開。

討論時不能取得其他人的本提案實際票型。此時只能比較：

- 兩次已結束提案的公開投票；或
- 前次公開投票與對方本次**口頭宣稱**。

不能把對方尚未公開的真實投票或內部快取當作台詞證據。「上次／這次」也必須綁定明確的提案 ID，避免混淆遠征輪次與同輪第幾次提案。

### G. `G17` 的可選事件與必填 placeholder 需要逐句判斷

`G17` 將公開事件參照標成 optional，但其中一句包含「第【輪次】次提案」。

沒有明確提案參照時，仍可選另一句不需輪次的安全回覆；不能任意填入目前遠征編號。placeholder 完整性應檢查到每句模板，而不是只檢查整個群組。

`【目標】` 也需要統一格式：有些句子後面已有「號」，有些沒有。應分開定義玩家編號與完整玩家稱呼，避免出現「3 號【小明】號」。

### H. `XLD04` 的矛盾查驗情境需要限定來源

目前規則中，被湖中女神查驗的人接手女神，之後不能再被合法查驗。因此，不能用「兩次正式查驗同一人」作為常態觸發前提。

同一持有者改口、互相衝突的轉述或玩家的公開宣稱，仍可形成對話矛盾。需要記錄宣稱來源與對應的正式查驗事件，避免把這些說法當成兩筆實際私人查驗。

## 3. V2 對現況的診斷：哪些已成立，哪些需修正措辭？

| 規格項目 | 對照程式後的判斷 |
|---|---|
| B01 固定邪惡名額與先驗 | 現有未知者起點確實是邪惡數／總人數，之後才覆寫本人等資訊。V2 改為扣除已知席位是合理改進；目前值屬主觀分數，不是程式宣稱的真實機率 |
| B02／B07 遠征歸因與獨立風險 | 確實仍是簡化加減分與獨立模型，尚未加入固定名額的聯合配置 |
| B03 成功不等於清白 | 現在只減 0.025，且本人私人情報會重新覆寫軟評分；已是弱證據設計，可進一步改成策略似然 |
| B04 翻劍雙向推理 | 現有減一張是在取得保守的未解釋失敗下界，不是在宣稱原始失敗張數一定等於最後張數減一；它會丟失資訊，值得升級，但不宜直接稱為改錯裁判結果 |
| B05／B06 蘭斯洛特時序 | 目前會大範圍降低舊情報確定性，尚未逐人建模是否可能是蘭斯洛特。V2 的精細處理合理，但「已知不是蘭斯洛特」必須從合法資訊推導，不能讀裁判的角色表 |
| B08 評分尺度 | **目前程式一致**：風險使用 0～1，自己入隊加 0.08，亂數不到 0.06。中文文件的 8 分／6 分是乘 100 後的說明，不是現有單位 bug |
| B11／B12 邪惡出牌 | 原始高破壞率、席位協作與關鍵局優先的順序確實存在，策略值得改進；尤其不要把不認識隊友的角色當成完美協作者 |
| B13～B16 女神、劍與刺殺 | 現有皆為啟發式評分，沒有完整期望效用或獨立的梅林信念模型 |
| B17 發言與記憶 | 現有只有六個主句、簡單歷史補充與女神宣稱；沒有事件型對話規劃器、問題佇列或語意去重 |
| 投票快取時機 | 現在是首次發言／投票時才按 BOT 快取，不是提案建立時一次凍結全員。V2 若改成提案建立即快取，屬明確的行為變更 |

## 4. 目前已有的基礎與真正缺少的模組

| 能力 | 目前狀況 | V2 要增加什麼 |
|---|---|---|
| 遊戲裁判、合法動作、擴充 | 已有 | 沿用現有規則，不將策略權重寫入裁判 |
| 每位 BOT 的資訊隔離 | 已有 `BotObservation` 與各自的私人記憶 | 增加來源 ID、適用時間及可比較的事件參照 |
| 公開投票與遠征歷史 | 已有 | 建立穩定的事件／提案 ID 與證據帳本 |
| 分離查驗事實與公開宣稱 | 已有初步結構 | 增加更多宣稱種類、轉述關係與可比較時間 |
| 角色化台詞 | 尚無通用載入與篩選器 | JSON 資產、型別轉換、條件映射、逐句 placeholder 檢查 |
| 回應別人的問題 | 尚未支援 | 問題對象、參照事件、回覆關係與真人「質疑／詢問」按鈕 |
| 主觀信念 | 簡單分數 | 知識帳本、固定名額約束、必要的候選世界與角色時序 |
| 回放與決策理由 | 可注入種子做測試，但未保存完整決策追蹤 | 對局種子、決策序號、證據 ID、策略與分數記錄 |
| 語音與自由對話 | 沒有 BOT TTS／ASR | 本次 V2 核心可先不做，保留接口 |

## 5. 建議實作順序

1. **先定資料契約**：統一角色、意圖、宣稱政策、條件名稱與 placeholder，讓未知條件安全停用。
2. **升級知識模型**：修正先驗、本人出牌與翻劍雙向約束、蘭斯洛特時序，完成不可見身分替換測試。
3. **改善行動策略**：再以新信念調整選隊、投票、關鍵出牌與劍的效用。
4. **接入事件型台詞**：先選可由現有公開資料支援的高頻情境；接話類規則待問題資料與按鈕完成後啟用。
5. **分層驗證**：push 時保留快速的單點與擴充流程測試，大量 5,000～10,000 場平衡模擬放在獨立的手動／排程工作，按配置輸出結果。

候選世界的 210 種只涵蓋 10 人局的二元邪惡席位配置；加入蘭斯洛特身份及梅林候選後狀態更多。實作前應決定快取、合併或取樣策略，並量測手機端決策時間。

本次沒有修改三份 V2 輸入文件，也沒有將它們註冊進 App。下一步可先處理上述接入前差異，再依階段實作。
