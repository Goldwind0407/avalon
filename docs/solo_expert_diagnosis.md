## 已確認的原因

| 問題 | 具體程式行為 | 本次處理 |
| --- | --- | --- |
| 討論不能改票 | `SoloGameSession._changed()` 在第一句發言前填滿 `_plannedVotes`，正式投票沿用 | `BotVotePlan` 分初始意向、發言前重評、討論結束後鎖定。每次重評使用同一 seed，不重抽偽裝偏好 |
| 高手對新說法反應弱 | `suspicion()` 原本先加發言影響，再由 `_deduce()` 以高手 0.9 的推理比重混合，留下約一成發言影響（仍不確定的席位） | 先推理再處理公開說法；所有合法候選配置都成立的結論與本人私人確定資訊仍優先 |
| 重複發言可以灌分 | 同一人對同一目標的每次指控、宣稱都再次加權 | 同一作者／目標只用最後一份立場；查驗宣稱分轉換狀態去重；組隊立場每提案只算最後一次；引述不當成新的本人宣稱 |
| 安全的雙失敗任務也被反對 | 原本只要隊上一人超過嫌疑門檻便否決，無論是否需要兩張失敗 | 單人嫌疑否決限於一張失敗即輸的任務；雙失敗任務按整隊失敗張數風險判斷 |
| 發言把結果說錯 | 工作分支 `BotVoice` 用 `fails > 0` 找資料，卻說「任務失敗」 | 改說「出現失敗牌」；用劍的任務不直接據此指認原始出牌者；轉換前的參與線索不直接用來指控現在陣營 |
| 台詞僵硬／重複 | 每情境兩句，另用隨機口頭禪包裝；主動發言繞過原台詞記憶 | 重寫 105 組 × 4 句；記住最近 12 句原文、提高相同論點扣分；主動指控同一目標沒有新任務／投票紀錄時不再重講同一論點 |
| 主動性不足 | 主動指控需舊紀錄，但被直接指控也可能跳過；沒有持續目標 | 優先回答本輪對自己的指控；有證據時維持指控／陷害目標，換邊、證據不符或本次投票不相容時重選 |
| 不容易知道投票原因 | 對玩家只看到一張票 | 私人 `BotVoteDecision` 記錄嫌疑、隊伍風險、選擇與原因；開發模式討論紀錄提供檢視器 |

## 改票與資訊權限

1. 提案出現時，每位 NPC 建立自己的初始計畫。
2. 輪到他發言時，以當下合法觀察重評。公開宣稱的組隊立場必須符合此刻計畫。
3. 進入投票階段時，所有 NPC 使用同一批討論紀錄、各自的私人觀察完成最終重評，再一次鎖定。其他人的改口公告也不會在這輪造成先算後算的差異。
4. 若曾公開表態而最終改變，追加 `reassess` 發言、引用討論中的公開發言；投票畫面提示有玩家改口，完整原因在討論紀錄。
5. 進入投票後不再改票；部分已送出的票仍不公開，也不會成為 NPC 的觀察輸入。

改口解釋描述的是「重新衡量公開討論」，不是宣稱其他人的說法已證實。它目前引用最近一則相關公開立場，並非逐句反事實分析，不能解讀成該句是唯一原因。

梅林刻意偽裝、壞人支持有破壞機會的隊伍仍保留。不能用「所有 NPC 都必須反對可疑隊伍」當測試。私人理由、策略目標與規則 ID 不寫入公開發言、筆記本或 Firebase。

G23 的「故意先表態支持，最後暗投反對」仍停用。本次允許的是有公告的重評，沒有啟用未公告的欺騙票。

## 台詞修改入口

直接讀／改 [bot_dialogue_natural.txt](bot_dialogue_natural.txt)。一行一個情境，四句以 `|` 分隔，人物與事件保留 `{{target}}` 等欄位。這是 420 句完整改寫，不是加口頭禪湊數。

原始 JSON 保留情境、角色與觸發條件；產生器會把新台詞覆蓋到正式 catalog：

```sh
python tool/prepare_bot_dialogue.py
python tool/prepare_bot_dialogue.py --check
```

每組必須四句不重複、ID 完整、變數合法。仍有 104 組可觸發，G23 保留文案但不執行。`BotVoice` 的主動回應是另外依公開人物／紀錄組句；不同玩家可能仍會有相似觀點，這不是保證整場沒有重複意思。

## 互動與開發檢視

- 現有「懷疑、相信、問」保留，新增「問投票」。只引用最後一份已公開投票，不讀正在投的票。沒有歷史時停用按鈕。
- NPC 被直接指控會回應指控者；被問票時能引述自己的實際公開票，再說現在的立場。
- 開發版：開啟「討論紀錄」→「NPC 決策（開發模式）」。可看初始／目前票、是否鎖定、嫌疑、風險與偽裝理由。release 沒有此入口，getter 也回傳空集合。
- 原有自由文字僅是關鍵字解析，不是理解自然語言或語音；複雜否定、多目標、引述仍應使用結構化按鈕。

## 測試與實測界線

- `bot_feedback_test.dart`：新說法改變高手票、同 seed 重評不重新抽籤、鎖票後不改、重複指控不灌分、私人確定資訊不被覆蓋、被指控回應、引用實際票、成功但有失敗牌不誤說任務失敗、雙失敗門檻、四句輪替。
- `solo_session_test.dart`：674 場各人數／擴充完整對局，檢查最後公開立場與實際票一致；改口必有 `reassess`、來源及引用，並維持原有隱藏資訊檢查。
- `bot_selfplay_test.dart`：新增 5／7 人各 40 場含發言的高手對局，統計回應與重評改票；舊的無發言對局仍保留做策略基準。
- 原本難度測試要求 600 場樣本中對新手邪惡的勝率必須嚴格較高；本次出現 30.67% 對 31% 的兩場差距。改為有明確 4 個百分點回歸容忍值，避免把極小差距當作難度結論；這個檢查不再宣稱已證明難度單調變強。

自動測試可證明事件流程、資訊權限與固定樣本行為，不能證明「台詞像真人」或「高手強度已平衡」。仍需手機實際遊玩，特別觀察改口是否容易找到、四種句子是否自然，以及有玩家提出錯誤指控時的反應。

本次本機驗證：`flutter test --no-pub` **256 項全數通過**（含上述批次模擬），`flutter analyze --no-pub` 無問題，台詞產物檢查通過。5／7 人各 40 場討論模擬分別記錄 334／434 次回應、5／4 次初始與最終票不同。這些是固定樣本的流程驗證，不是改版前後勝率提升的證明；尚未進行這版手機真人驗收，也未宣稱 GitHub CI 已執行這批工作目錄修改。

## 還需要的下一階段

目前 `BotStrategyPlan` 是跨提案的發言目標，不是完整組隊／發言／投票共同最佳化器。投票仍是風險與角色行為啟發式，尚未加入下一位隊長的預測收益、拒絕後局勢搜尋、長期信任效用與完整梅林身分後驗。

下一步應先記錄足夠的實測對局，再比較「公開說法可信度」「拒絕後的替代隊伍」「陷害是否真的影響他人」；不要僅靠調低高手容忍值讓所有人一直反對。任意公開指控目前只能造成有限的軟影響，不能直接當成確定身分。
