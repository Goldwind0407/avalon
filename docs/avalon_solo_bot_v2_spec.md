# 阿瓦隆單人電腦 AI V2：數值平衡、發言邏輯與功能規格

> 狀態：設計草案，待 Dart 實作及模擬驗證  
> 基準文件：`solo_bot_rules.md`（目前已實作規則的說明）  
> 日期：2026-11-12  
> 範圍：5～10 人單人模式（1 位真人，其餘 BOT）、基本角色、湖中女神、兩種蘭斯洛特變體、王者之劍。實際合法行動仍以 `game_model.dart` 為準。  
> **重要限制：本規格只根據提供的 Markdown 文件推導；尚未直接檢查 Dart 原始碼，文中的「風險」是待驗證設計問題，而非宣稱程式存在確定的 bug。**

## A. V2 的目標與原則

### A1. 驗收目標

1. **有根據地推理**：BOT 能用角色可見情報、公開遠征、投票、查驗和翻牌，對未知玩家更新相互關聯的推論。
2. **符合角色立場**：正義盡可能使任務成功；邪惡在破壞、藏身、誤導、刺殺間取捨；梅林兼顧保護身分。
3. **會討論且前後一致**：同一提案不任意改變預定投票；發言能引用具體事件並回應反對意見。
4. **擴充能改變策略**：湖中女神、蘭斯洛特和王者之劍不只新增動作，也影響核心信念及出牌。
5. **不作弊**：BOT 不能從裁判私有真相取得超過自己角色允許知道的資訊；可說謊，但不可以不當取得情報。
6. **可以量測**：每次決策記錄可重播的理由和隨機種子，透過自動對局評估品質。

### A2. 非目標

- V2 不要求完整自由語音聊天或預先手寫每條遊戲歷史分支。
- 不把「懷疑值」宣稱為經校正的真實機率，直到模擬資料足夠並通過校正驗收。
- 不直接把 LLM 變成裁判、出牌器或能看見全員身分的策略核心。

## C. 數值與演算法

### C1. 固定邪惡名額與私人資訊

對某 BOT：`unknownEvilCount = evilSeatsTotal - definitivelyKnownEvilSeats`，`unknownSeatCount = totalSeats - definitivelyKnownGoodSeats - definitivelyKnownEvilSeats`。未知席位的均勻先驗為 `unknownEvilCount / unknownSeatCount`，須先處理自己及角色可見的約束。

**例子**：5 人、2 邪惡、某正義 BOT 除自己外沒有情報：其餘 4 位未知玩家每人的先驗是 2/4 = 50%，不是 2/5 = 40%。如果開局已確定其中 1 位邪惡，則另外 3 位未知玩家的先驗是 1/3。

更重要的是保留「恰有幾個邪惡」的相關性：5 人局剩餘 4 人恰有 2 惡，從其中抽 2 人，至少一位邪惡的機率為 `1 - C(2,2)/C(4,2) = 5/6 ≈ 83.33%`。這並不表示遠征一定有 83.33% 的失敗率；邪惡能出成功，還要另外計算出牌政策。

### C2. 懷疑模型：兩階段演進

**V2.0（較快落地）**

- 把所有線索保存為 `Evidence`，分為 `hard`、`private`、`public`、`statement`、`derived`。
- `hard`：BOT 自己目前的身分、角色規則下可見的確定敵人、在合法前提下看到的原始失敗牌等；不得被公開謠言推翻。
- 事件只更新一次；對同一遠征的「失敗 + 隊長選人 + 發言」避免機械重複加權。
- 遠征失敗牌歸因時，先排除已知自己出的未翻轉失敗牌，再考慮所有能提供失敗牌的隊員及翻劍未知。
- 提案、投票、發言屬軟證據。投反對不必然代表好人，挺可疑者也不必然是邪惡。

**V2.1（建議的正式模型）**

- 枚舉符合玩家數、邪惡總數與角色資訊的候選世界 `WorldHypothesis`（包含必要的蘭斯洛特狀態），為每個假設賦權重。
- 每次公開任務結果、已知自己的牌、女神私查、劍私查後，用 `P(observation | world, observed decisions)` 更新權重。
- 對所有世界加總得 `P(玩家i當前為邪惡)`、`P(某隊有至少k位邪惡)`、`P(玩家i為梅林)` 等。
- 在 10 人局，純粹選擇「哪些人是邪惡」的組合最多是 `C(10,4)=210`；實際再加入角色與時序資訊會增加狀態數。可採假設合併、Top-K 或取樣，不必列舉完整的對話樹。
- **不得把邪惡一定會出失敗當成觀察假設**；改用會隨局勢變化的出牌似然，以免好人錯誤地把成功當作清白證據。

### C3. 遠征風險分兩層

```text
teamEvilProbability(team, k) = P(至少 k 位當時邪惡在隊上 | BOT 自己可見的情報)
questFailProbability(team, context) = Σ_h P(h | evidence) × P(任務失敗 | h, context, evilPolicy, swordPolicy)
```

- `questFailProbability` 必須跟遠征的失敗牌門檻連動，並且考慮蘭斯洛特變體二的強制失敗、翻劍改牌。
- 強制失敗的規則是明確約束；一般邪惡出失敗只是一項策略機率。
- `teamEvilProbability` 只代表陣營配置，不要把它說成任務結果的準確預測。
- 推理內可以用一份穩定的「對手行為模型」來預測；自身邪惡出牌則可使用不同的「最佳反應政策」，避免同時把預測值當成實際出牌。

### C4. 組隊效用（示意，不是已校正公式）

**正義隊長**

```text
scoreGood(team) =
  + 0.70 * estimatedQuestSuccess
  + 0.12 * usefulInformationGain
  + 0.10 * knownGoodCoverage
  - 0.08 * MerlinExposureCost
  + tieBreakNoise
```

**邪惡隊長**

```text
scoreEvil(team) =
  + 0.60 * estimatedEvilVictoryProgress
  + 0.20 * perceivedCredibilityGain
  + 0.15 * chanceToPlaceUsefulSaboteur
  - 0.05 * exposureCost
  + tieBreakNoise
```

係數皆是**待測的起始相對權重**；各項需先正規化到 0～1。正義不必每次都選自己；邪惡也不必每次都選自己。先對所有合法隊伍評分，再從前 2～3 名依分數權重抽樣；中高難度減少抽樣雜訊。

### C5. 投票建議

**正義：**比較 `U(批准本隊)` 與 `U(否決、讓下一位隊長提案)`，包括本隊勝率、可取得的資訊、未來隊長可能性、目前失敗次數與連續否決次數。無法可靠預測下一隊時，暫時用「本隊風險相對於可選最佳隊伍風險」而非全局 65 當唯一條件。

**邪惡：**考慮通過後的任務收益、是否會暴露同陣營、自己能否接任隊長，以及投反對後的輿論代價。連續 4 次否決時，若現有遊戲規則第 5 次否決直接讓邪惡勝利，邪惡投反對、正義投贊成皆是硬規則。

**V2.0 相容性：**可保留原始 65／48 作 fallback，但必須把每次決策記錄 `currentRisk, bestFeasibleRisk, rejectionCount, predictedNextLeader`，以便後續替換。

### C6. 邪惡出牌政策：建議作為實驗參數

| 情境 | 建議策略 | 初始嘗試參數（非最佳解） |
|---|---|---|
| 第一場、自己是唯一可確信邪惡、任務不決勝 | 可藏牌以建立可信度 | `pFail ≈ 0.50～0.70` |
| 已知同隊邪惡、只需一張失敗 | 使用穩定的座位約定，減少不必要雙失敗 | 被指定破壞者 `pFail ≈ 0.85～1.00` |
| 已知同隊邪惡、需要兩張失敗 | 優先保證足夠失敗牌，不可讓兩人都因隨機而出成功 | 關鍵兩位 `pFail ≈ 1.00`（規則允許時） |
| 本次失敗可直接取得第 3 次邪惡勝利 | 當場獲勝優先於保持隱藏 | 能使任務失敗則以極高機率破壞 |
| 敵方劍持有者可疑、可能翻自己的失敗牌 | 出成功有時更有利，利用對方翻劍造成失敗 | 根據翻劍預測調整，不用固定 % |
| 目前已是正義的蘭斯洛特 | 必須出成功 | `pFail = 0` |
| 變體二目前為邪惡且規則強制失敗的蘭斯洛特 | 必須出失敗 | `pFail = 1` |

**注意：**不認識彼此的邪惡角色（例如奧伯倫、依實際規則孤立的蘭斯洛特）不得偷讀隊友的出牌意圖；他們的協作只能透過公開席位慣例、已獲得的合法情報與獨立估計。

### C7. 湖中女神

目標分數：

```text
ladyValue(target) =
  0.50 * expectedInformationGain
+ 0.25 * relevanceToUpcomingQuests
+ 0.15 * abilityToInfluencePublicVote
+ 0.10 * publicContradictionPotential
```

在合法可查範圍選擇最高分，不只選最接近 50% 的人。持有者如實知悉查驗結果，但公開發言依角色立場制定「真實／誤導／略過強烈指控」的策略，並儲存 `actualInspectionPrivate` 與 `publicClaim` 兩種獨立紀錄。邪惡說謊是否有利取決於查驗目標、已知矛盾、說謊後是否容易被查驗者反駁，不建議永遠固定 45%。

### C8. 蘭斯洛特時序模型

```text
KnowledgeFact {
  targetSeat,
  observedAtQuest,
  observationType,
  observedAlignment,
  canTargetBeLancelot,
  appliesAtCurrentSwitchState
}
```

- 非蘭斯洛特玩家的陣營不會因為全域轉換狀態改變。
- 不知道哪位是蘭斯洛特時，將「該玩家是蘭斯洛特」當成不確定假設，再結合現在已公開的轉換狀態更新；不要將所有舊情報直接乘上 40%。
- 對過往任務，判斷當時陣營；對下一任務，判斷預期當前／未來陣營。
- 若變體公開下一張轉換牌，可前瞻比較下一輪敵我配置，但不能推斷未公開角色座位。

### C9. 王者之劍的期望效用

- 送劍：評估候選持劍者「是否可相信」及「能否有益地翻牌」，不是單純信任程度。邪惡隊長考慮送給已知邪惡隊友，避免讓可信正義持劍者有利使用。
- 用劍：`expectedUtility(flip(target)) - expectedUtility(noFlip)`；納入目標原始牌為失敗的估計、其他隊員失敗牌分布、兩張失敗門檻、是否為決勝局及翻牌可得到的私人資訊。
- 若目標原先失敗，翻劍會減少失敗牌；若原先成功，翻劍會增加失敗牌。公開結果不能一律假設「扣一張」。
- 持劍者看到原始牌才取得硬證據；其他觀察者只知道翻牌發生，不知道原始牌。
- **理論直覺**：若假設與其他人的出牌獨立，且其他隊員恰好出 `失敗門檻−1` 張失敗的機率為 `r`，翻目標牌對任務成功率的期望改變約為 `r × (2q−1)`，其中 `q` 是目標原始牌為失敗的概率。這說明固定「懷疑≥62」不是通用翻劍規則。

### C10. 刺殺與梅林防暴露

- `GoodProbability` 與 `MerlinProbability` 分開追蹤。
- 梅林候選證據：多次提前避開其他邪惡也不了解的邪惡玩家、在公開資訊不足時做出準確選擇、長期一致的資訊精度、對已知邪惡的態度。
- 反證：明顯只是跟隨先前失敗隊伍的公開資訊、不具備先知性、發言刻意借用別人證據。
- 梅林 BOT 在選隊和說話時可適度掩護資訊來源，避免每次都以「完美資訊」作出可被刺客辨識的行為。不得為了演戲而擅自違反法定動作。

## D. 發言引擎 V2

### D1. 架構：先決策，再決定發言

```text
合法 Observation（公開事件＋自己合法的私人記憶）
    ↓
BeliefEngine：每位玩家的信念、事件證據、可信度
    ↓
ActionPolicy：預定選隊／投票／出牌／道具行動
    ↓
DialoguePlanner：這一回合想達成的溝通目標
    ↓
DialogueAct：立場、對象、可引用的證據、可能說謊的主張
    ↓
TemplateRenderer（V2）／受限制的 LLM 改寫（後續）
    ↓
討論紀錄（可選 TTS）＋ SpeechMemory（避免重複）
```

不能讓文字生成器倒過來決定投票。真正的投票在提案建立時快取；如果台詞是有意說謊，公開投票不必和口頭宣稱相同，但這必須是明確策略並進入矛盾記憶，而不是每一句重骰。

### D2. DialogueAct 建議資料結構

```dart
enum SpeechIntent {
  supportTeam, opposeTeam, demandReason, accuse, defendSelf,
  defendOther, challengeVote, pointOutContradiction, quoteQuest,
  interpretLady, challengeLady, discussSword, discussLancelot,
  bluff, hedge, warnFifthVote, proposeAlternative, apologize,
  reassessBelief, misdirect, abstainFromJudgment
}

class DialogueAct {
  final int speakerSeat;
  final SpeechIntent intent;
  final int? targetSeat;
  final List<String> publicEvidenceIds;
  final bool plannedApprove;
  final String? claimType;
  final double intensity; // 0.0～1.0
  final String semanticKey; // 避免同義句反覆出現
  final int questIndex;
  final int proposalIndex;
}
```

`DialogueAct` 的外顯證據必須可追溯到公開事件；私人線索只可以影響「要說什麼」，不可不小心被模板印出。梅林可能沒有公開證據仍想反對，此時應用「我想比較其他組合」而非「我知道 3 號是邪惡」。

### D3. 台詞意圖與模板（可直接實作的初始集合）

| 觸發條件 | SpeechIntent | 示例台詞 |
|---|---|---|
| 贊成，風險低 | supportTeam | 「這次隊伍的組合比上一隊穩定，我會支持。」 |
| 贊成但資訊少 | hedge | 「我沒把握這隊全是好人，但目前值得試一次。」 |
| 反對，有特定可疑席位 | opposeTeam | 「我反對的重點是 {target} 號，不是整隊都不可信。」 |
| 隊長重複失敗隊伍 | quoteQuest | 「第 {quest} 次遠征的組合已經出現過失敗，為什麼還要讓 {target} 上？」 |
| 隊伍只換一人 | demandReason | 「只換了 {old} 號成 {new} 號，你這次改人的依據是什麼？」 |
| 前次贊成現在反對 | challengeVote | 「{target} 號，這隊只換了一個人，你的投票立場卻反過來了？」 |
| 有人指控自己 | defendSelf | 「你可以懷疑我，但請說是哪一場遠征讓你有這個結論。」 |
| 有人受指控，BOT 認為證據不足 | defendOther | 「我不認同現在就鎖定 {target} 號，一張失敗牌不能只算在他身上。」 |
| 連續四次否決 | warnFifthVote | 「已經是第五次提案，再否決就輸。我這票會贊成。」 |
| 第四任務要兩張失敗而只有一張 | quoteQuest | 「雖然那一場遠征成功了，但出現一張失敗牌，不能當作全員清白。」 |
| 本人女神查到邪惡，選擇公開 | interpretLady | 「我查驗到 {target} 號當時是邪惡，但仍要注意蘭斯洛特的轉換。」 |
| 女神宣稱與過往發言衝突 | challengeLady | 「你現在說 {target} 是好人，可是前一輪你還把他列為最可疑？」 |
| 劍被使用後任務失敗 | discussSword | 「這張失敗牌有可能是翻劍造成的，不能直接拿來指控原本出牌的人。」 |
| 蘭斯洛特發生轉換 | discussLancelot | 「轉換發生了，舊的查驗只能證明當時的狀態。」 |
| 邪惡選擇掩護隊友 | misdirect | 「與其只盯著 {target} 號，我更想看隊長為什麼維持原隊。」 |
| 邪惡故意示弱 | bluff | 「你們可以先不信我，但下次遠征我願意用投票證明立場。」 |
| 同一推論多次被證偽 | reassessBelief | 「我上一輪的判斷可能不準，現在會降低對 {target} 號的懷疑。」 |
| 公開證據不足且高度重複 | abstainFromJudgment | 「目前沒有新線索，我不想再重複同一個猜測。」 |

### D4. 發言挑選規則

**對話狀態**：

- `publicStatements`：所有可引用的發言、回合、證據 ID。
- `speakerClaims`：每個玩家曾說過的可追蹤主張（支持誰、指控誰、聲稱查驗結果）。
- `speechMemory`：上一次意圖、語意鍵、提及誰、是否已被回應。
- `pendingQuestions`：他人點名的問題、優先回應期限、是否答覆。
- `privateObjective`：梅林避免曝露、邪惡製造矛盾、派西維爾保護候選梅林等；不得直接輸出秘密欄位。

**候選台詞分數**：

```text
speechScore =
  + evidenceRelevance
  + answersDirectQuestion
  + currentStrategicValue
  + characterStyleFit
  - repeatedSemanticPenalty
  - contradictionRiskUnlessIntentional
  - illegalInformationLeakPenalty(無限大)
```

**節流建議**：每個提案最多 1 句主句 + 1 句情境補充；有被點名時優先回覆，沒新線索時允許不發言。相同 `semanticKey` 在最近 2 個提案內盡量不重複；整場不要反覆引用「第一場失敗」，改選對目前隊伍最有關係的一場。

**玩家說話接入（後續）**：先用結構化按鈕（支持、反對、質疑某人、要求說明），再接 ASR→意圖解析→證據驗證→DialogueAct。不能直接把未經確認的語音辨識文字變成已證實事實。可選 TTS；語音模型只是將決定的內容讀出或改寫，不負責偷看身分與裁判。

### D5. 陣營與角色的發言差異

| 角色／情況 | 主要溝通目的 | 禁止或避免 |
|---|---|---|
| 一般正義 | 說明公開證據、質疑不穩定隊伍 | 把推測當成確定情報 |
| 梅林 | 引導好隊伍且隱藏自己知道過多的跡象 | 揭露只有梅林能知道的精確私人理由 |
| 派西維爾 | 比較兩個可見候選、避免暴露梅林 | 直接把兩候選都當成真梅林／同陣營 |
| 一般邪惡 | 製造替代嫌疑、替隊友提供公開理由 | 神準指出自己無權得知的情報 |
| 奧伯倫 | 單獨推理及偽裝 | 把未認得的邪惡隊友當成確定盟友 |
| 邪惡／正義蘭斯洛特 | 依現有陣營與公開轉換資訊決策 | 回頭把舊陣營當作永久不變 |

## E. 新功能規格（供 Dart 開發）

### E1. 模組拆分

| 模組 | 責任 | 是否優先 |
|---|---|---|
| `BotKnowledgeLedger` | 合法資訊、公開與私有事件、來源與時序 | P0 |
| `BotBeliefEngine` | 更新相互關聯的敵我推論、保留理由 | P0 |
| `BotQuestPredictor` | 按隱藏世界與角色行為預測出牌、翻劍、任務結果 | P0 |
| `BotPolicyEngine` | 組隊、投票、出牌、女神、蘭斯洛特、劍及刺殺 | P0～P1 |
| `BotDialoguePlanner` | 從局勢與行動產生 DialogueAct | P1 |
| `BotTemplateRenderer` | 變化句型、套入合法公開證據、限制重複 | P1 |
| `BotSpeechMemory` | 管理曾說過的主張、回答、矛盾 | P1 |
| `BotPersonalityProfile` | 個性與語氣偏好，不給特殊視野 | P2 |
| `BotDifficultyProfile` | 改推理深度、行動隨機性與失誤頻率 | P2 |
| `BotSimulationHarness` | 無 UI 自動對局、固定種子、重播與統計 | P0 |
| `BotDecisionTrace` | 只供測試與開發畫面使用的決策理由 | P0 |

### E2. 介面與資料契約（示意）

```dart
class BotContext {
  final BotObservation observation;   // 不含全員身分表
  final PublicEventLedger publicEvents;
  final BotPrivateMemory privateMemory;
  final BotDifficultyProfile difficulty;
  final int randomSeed;
}

class BotBeliefSnapshot {
  final Map<int, double> currentEvilBelief;
  final Map<int, double> merlinBelief;
  final List<EvidenceExplanation> explanations;
  final int questIndex;
}

class BotDecision<T> {
  final T action;
  final String strategyTag;
  final List<String> evidenceIds;
  final Map<String, double> traceScores;
  final int seed;
}

abstract class BotPolicy {
  BotDecision<Team> chooseTeam(BotContext c);
  BotDecision<bool> vote(BotContext c, Team team);
  BotDecision<QuestCard> questCard(BotContext c);
  BotDecision<int> ladyTarget(BotContext c);
  BotDecision<int> swordHolder(BotContext c);
  BotDecision<int?> swordTarget(BotContext c);
  BotDecision<int> assassinate(BotContext c);
}
```

實際欄位、Dart 型別與現有函式介面需依程式架構調整。`BotDecisionTrace` 僅供內部測試與結算後檢視，對玩家不可暴露秘密或尚未公開的推理依據。

### E3. 規則引擎與 AI 的界線

- `game_model.dart` 永遠是合法動作、角色身分、擴充和勝負的唯一裁判。
- `solo_session.dart` 只負責階段、將合法 observation 投遞給 BOT、取得動作、寫入公開事件、播報與暫停。
- BOT 只操作 `BotObservation` 與自身記憶，不取得 `GameState` 裡的完整身分資料。
- 若要讓 BOT 分析「可行世界」，須由它根據合法事件自己推演，而非由裁判提供真相快照。
- 相同 `BotContext + seed` 應得到可重現的決策；討論發言使用同一份已快取的本輪投票立場。

### E4. 界面需求

- 遊戲畫面可顯示 BOT「目前立場」與對應公開依據，**不能**提前顯示隱藏身分判斷。
- 玩家可點擊「快轉 BOT 發言」或「略過非關鍵討論」，保留完整公開紀錄。
- 開啟討論、筆記、規則、離開確認、進入背景時，暫停現有 BOT 操作和發言倒數。
- 開發模式有「AI 決策追蹤」查看 score、seed、證據 IDs；正式版不向玩家曝露秘密。

### E5. 測試與驗收

**資訊隔離**

- 兩個真實世界對某 BOT 的合法觀察完全一樣時，使用相同種子應得到相同的決策分布，不得因隱藏身分變動而改變結果。
- 梅林不能憑空看見魔德雷德；派西維爾看到兩位候選時不得直接區分梅林／莫甘娜；奧伯倫不得知道未認識的邪惡隊友；蘭斯洛特依現有變體可見性驗證。

**特殊情境**

- 5 人正義 BOT 未知四人中有兩惡，起始 50%。
- 兩人遠征 BOT 自己是好人且出成功，沒有劍介入，最終出現一張失敗牌：另一隊員當時必為邪惡。
- 7 人以上第四遠征只有一張失敗牌，任務成功但仍記錄「有人出失敗」。
- 王者之劍將成功翻成失敗，以及將失敗翻成成功兩種方向，公開與私人推理不能混淆。
- 蘭斯洛特轉換前後，對固定陣營角色的已知情報不應無端失效；舊查驗只綁定當時陣營。
- 第五次提案：正義 BOT 不得投否決；邪惡 BOT 可依現有規則投否決直接爭勝。
- 變體二邪惡蘭斯洛特必須出失敗；正義玩家不得出失敗。
- 同一提案先發言後投票，預定投票與行動一致，除非明確設計了說謊型公開聲明。
- 重新發牌、重開局、背景切換、跳過發言，不得留下上局私有記憶或重複計入證據。

**發言驗收**

- 至少涵蓋 15 個高頻 DialogueIntent，每個意圖至少 3 個可替換的語意模板。
- 針對被點名、查驗矛盾、翻劍、轉換、關鍵兩失敗、第五次提案，須有獨立觸發條件。
- 同一玩家不得長期連續重複同一模板；說出「第 X 次」的事件編號和隊員必須可從公開紀錄追溯。
- AI 台詞不能捏造從未發生的投票或任務結果，除非是在有意策略性說謊且系統有記錄該說謊行為的情況；絕不偽造裁判已公開的客觀紀錄。

### E6. 自動平衡測試

每個設定至少 5,000～10,000 場、跨玩家數、角色配置、擴充開關、難度、種子分層抽樣。**這是建議樣本量，不是勝率承諾。**比較 V1 與 V2：

| 指標 | 解釋 | 期待觀察 |
|---|---|---|
| 正義／邪惡勝率 | 分不同配置與難度報告，不能只看整體平均 | 不因單一策略崩壞成極端勝率 |
| 關鍵任務破壞率 | 當邪惡有合法機會完成第 3 次破壞時是否真的出對牌 | 較 V1 改善 |
| 兩失敗任務失誤率 | 有足夠邪惡在隊上卻沒有產出足夠失敗 | 較 V1 降低 |
| 劍的淨效果 | 有劍與沒劍時對當前陣營的任務勝率影響 | 中高難度更少「翻錯」 |
| 女神情報價值 | 查驗後信念不確定度的下降、對下一隊的影響 | 比只選最接近 50 有效 |
| 梅林被刺中率 | 分玩家數、角色與是否開語音統計 | 避免梅林 BOT 因完美行為過於明顯 |
| 可解釋一致性 | 相同證據得到穩定判斷、發言沒有自相矛盾 | 高一致性，但可策略性說謊 |
| 台詞重複率 | 同玩家最近兩輪同義句重複比例 | 顯著下降 |
| 非法動作與資訊洩露 | 所有角色與擴充組合下的違規次數 | **必須為 0** |

模擬分成兩類：BOT 全自動自我對戰用來量測演算法穩定性；真人或規則式玩家混合對戰用來量測玩家體感，避免 AI 只學會對付同類 AI。

## F. 分階段開發計畫

| 階段 | 實作內容 | 完成定義 |
|---|---|---|
| **Phase 0：守住正確性** | C1 固定邪惡名額；翻劍雙向推理；蘭斯洛特時序；私有資訊隔離；評分尺度統一；基礎測試 | 規則與資訊隔離測試全部通過 |
| **Phase 1：策略 V2.0** | 遠征證據、動態出牌、雙方效用選隊與投票、女神／劍／刺殺改進；決策追蹤 | 5～10 人與擴充可連續自動對戰、結果可重播 |
| **Phase 2：會討論的 BOT** | DialogueAct、情境模板、SpeechMemory、被點名回應、關鍵事件引用 | 主要場景有合理台詞，重複率受控，不曝露私有資料 |

## H. 第一輪實作的最小版本（建議）

如果一次只能做五件事，依序為：

1. **修正先驗**：自己與所有已知席位扣除、保留邪惡名額限制。
2. **修正事件歸因**：本人出牌、翻劍雙向結果、兩失敗門檻、蘭斯洛特時序。
3. **調整邪惡出牌**：不再永遠高機率失敗；關鍵局與需要雙失敗時採強決策。
4. **建立事件型發言**：先做至少 15 種 DialogueIntent，每種 3 個句型，含引用、反擊與記憶。
5. **自動對戰與追蹤**：同種子可回放，按角色與擴充分組看勝率和決策失誤。

上述五件完成後，再決定是否值得加入聯合假設枚舉、更複雜的刺殺演算法與 LLM 自然語言表達。
