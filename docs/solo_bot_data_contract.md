# 單人 BOT V2：資料格式與資訊權限

本文件描述本次已接入 App 的部分。原始 V2 設計與台詞文件保留為草案；尚未具備條件的功能不算完成。

## 1. 資料流

```text
本機裁判 AvalonGame（持有全員秘密）
  → SoloGameSession._observe(某席位)
  → BotObservation（該玩家有權知道的值快照）
  → BotBrain（策略）／BotDialoguePlanner（發言）
  → DiscussionStatement（可公開的發言）
```

策略與台詞檔案不接收 `AvalonGame`、全員角色陣列、他人的私人查驗、他人的未公開任務牌或正在投的票。所有集合以不可變副本傳遞。每位 BOT 有自己的查驗記憶、本人任務牌、發言記憶和獨立亂數。

## 2. 統一識別方式

| 欄位 | 意義 |
|---|---|
| `generation` | 本次發牌的局號；重新發牌後不同 |
| `seat`／`target`／`speaker` | 程式內 0 起算席位；畫面顯示加一 |
| `quest` | 1 起算的第幾次遠征 |
| `attempt` | 同次遠征第幾個提案，1～5；不跨遠征累加 |
| `BotProposalId` | `g{generation}/q{quest}/a{attempt}` |
| `BotEvidenceId` | `g{generation}/{kind}/{key}`；只能在同局公開事件簿解析 |

通過提案後，即使否決計數歸零，任務階段仍沿用已通過提案的 `attempt`。遠征結果、女神查驗等過渡畫面使用 `activeQuest` 決定已發生事件，不把 `history.length + 1` 誤認成下一次已完成遠征。

發言的 `quest` 是它所屬的討論輪次；引用事件保留自己的遠征編號。例如女神在第 2 次遠征後使用，宣稱可供第 3 次遠征討論參考，但 `evidenceIds` 仍指向第 2 次的使用事件。

## 3. 角色與陣營

正式台詞角色 ID 為 `all`、`loyal`、`merlin`、`percival`、`minion`、`assassin`、`morgana`、`mordred`、`oberon`、`lancelotGood`、`lancelotEvil`。

- 草案 `loyal_servant`／`evil_minion` 由匯入器明確轉換。
- 裁判的 `Role.lancelotGood`／`Role.lancelotEvil` 仍代表初始角色。
- 台詞的蘭斯洛特角色 ID 依目前陣營選擇；不以初始角色決定換邊後要說哪種台詞。
- `BotObservation.switched` 和私人查驗的 `switched` 是累積轉換奇偶狀態；公開事件的 `switchOccurred` 表示那次牌是否觸發轉換，兩者不可混用。
- 變體二可見的未來牌保留為公開資料，但未來牌不登記成已發生的轉換事件。

## 4. 公開事件與私人證據

`BotPublicLedger` 只登記：提案、全員已完成的投票、遠征結果、女神使用者與目標、翻劍使用者與目標、已發生的轉換牌、公開發言。

事件簿沒有原始任務牌或女神真實陣營欄位。未完成的投票不能建立投票事件。事件引用帶局號，其他局的引用不能解析。

`BotFact` 必須指定 `owner` 和 `generation`，並且恰好包含 `evil`（女神結果）或 `originalCard`（劍前牌）其中之一。觀察快照拒絕不同持有者、不同局、未來遠征、不合法席位及兩種值混填的資料。本人任務牌也必須對應本人參加過的遠征或正在參加的任務。

私人查驗要出現在台詞中，還必須找到同局公開使用事件，確認使用者、目標和遠征都吻合。不能因為「有人用過女神／劍」就替其他 BOT 填入結果。自己的任務牌是另一個合法來源，不必假裝只有持劍者才知道原始牌。

## 5. 公開發言與私人計畫

`DiscussionStatement` 可公開：發言者、文字、遠征／提案、語意種類、指向席位、對女神結果的宣稱、明說的支持／反對、`questionTo`、`replyTo`、公開 `evidenceIds`。

對話回應另外使用明確欄位：`position`（質疑／辯護）、`certainty`（初步／確定／永久定性）、`quotedFrom`（引述來源）、`claimedOriginalSuccess`＋`originalCardQuest`（對原始牌的公開宣稱）、`claimsOpeningKnowledge`（宣稱有開局情報）。這些值描述玩家說了什麼，不代表宣稱為真。引述不算引述者本人的指控或親眼查驗。

`BotConversation` 只接收公開事件與發言。它依目前遠征／提案找到實際指控者、辯護者和提問者；無法解析的文字不會自行變成指控、保證或查驗宣稱。真人目前仍透過支持／反對按鈕表態，沒有自由文字／語音辨識輸入。

`BotDialogueTrace` 留在該 BOT 內部：台詞規則 ID、規劃立場、宣稱政策與去重記憶。角色專屬規則 ID（例如 `RME01`）本身可能洩漏身分，因此不放進公開發言欄位。

第一位發言前，所有 BOT 分別用自己的快照固定本提案的預定投票。台詞若明說立場，必須一致；中性句不附帶私人預定投票。其他 BOT 取得的是公開發言，不能讀取計畫快取。

同隊 BOT 也在此時固定本人的任務出牌計畫；未通過提案的計畫會丟棄。`plannedQuestSuccess` 只投影給本人，實際出牌沿用此計畫，讓「本輪藏牌」的台詞與後續行動一致。強制失敗與目前陣營仍由裁判驗證。

女神真相保存在持有者的 `BotFact`。公開宣稱另存 `claimedEvil`，即使說謊也不改寫真相。真實查驗與他人口頭宣稱不會共用同一欄位。

## 6. 台詞格式與執行

原始來源：[avalon_bot_dialogue_templates_v2.json](avalon_bot_dialogue_templates_v2.json)。執行資料由 `tool/prepare_bot_dialogue.py` 產生為 `generated/bot_dialogue_data.dart`，正式版本為 `schemaVersion: 1`。

每組包含 `id`、`role`、`phase`、`intent`、`policy`、`priority`、`requires`、`templates`；`scenario`／`sourceTrigger` 保留草案說明。中文觸發描述只作註解，不會當成程式碼執行。

五種政策為 `publicGrounded`、`privateTruthClaim`、`privateStrategyPublicClaim`、`strategicOpinionBluff`、`explicitPrivateClaimLie`。草案 G07 的 `intentional_opinion_bluff` 有明確別名；其他未知值會拒絕匯入／載入。

佔位符只允許固定集合，例如 `{{target}}`、`{{quest}}`、`{{attempt}}`、`{{fails}}`。人物代入完整 `3 號 【小明】`；遠征和提案次序使用不同欄位。未知格式會拒絕載入；缺少合法事件或人物的那一句會跳過，同組其他完整句子仍可使用。

執行順序：角色與階段 → 明確登錄的情境條件 → 所有必要條件 → 證據權限 → 每句佔位符 → 優先度與最近兩次提案的語意去重。未知情境或條件一律停用。無候選句時使用簡短立場句。

匯入時修正的語意：

- G16 比較兩次**已公開**投票，不讀取本次尚未投出的票。
- RME02 引用遠征參與和失敗牌，不把這個線索說成已證明的投票或隊長選人行為。
- XSW03 的成功→失敗只說增加失敗牌，不保證改變整場遠征結果。
- XSW04 對照公開的持劍者、被翻牌者與宣稱者；本人出的牌及合法持劍者都能知道原始牌，引述者也不會被當成聲稱親眼看過。只有缺乏這些來源的直接宣稱才會被追問。
- XLD04 比較同一個公開女神使用事件、相同轉換狀態的兩份相反宣稱；不會憑空產生兩次對同人的合法女神查驗。它只指出公開說法矛盾，不裁定哪個宣稱為真。
- RLS06 與 XVR01 是詢問辯護理由，正式 `intent` 改為 `challengeClaim`，避免把提問者又錯記成辯護者。
- RME04、RMG06、ROB05 引用實際遠征參與線索，不把它誤說成投票或隊長選人；RPC07 的兩份相反宣稱也不直接說成同一人改口。

## 7. 本批啟用範圍

共匯入 105 組、210 句，其中 **104 組已登錄執行條件，只有 G23 停用**。本批補上原先停用的 48 組，每組有符合條件的情境測試；已登錄不代表每場都會出現，仍須符合角色、階段及當場證據。

- 換隊說明：保留的人與被換掉的人分開綁定。
- 指控、辯護、追問：引用實際公開發言，分清被談論者與被提問者。
- 新證據修正：新失敗紀錄必須發生在被引用的辯護之後。
- 原始牌／女神宣稱：區分本人出牌、持劍者查驗、直接宣稱與引述。
- 蘭斯洛特：比對查驗後已發生的轉換；未來牌不算已轉換，兩次抵消的轉換不會讓當前陣營不同。公開差異不會直接被當成說謊。
- 影響力與刺客試探：只使用公開被辯護／被提問的紀錄及本人可見的線索，不讀對方真實角色。這是啟發式選擇，不是完整梅林身分機率。
- 刺殺宣言：目標由刺客先決定；裁判接受刺殺後才記錄公開宣言，不會預告另一個隨機目標。

**G23 暫停的原因**：它需要「故意公開說支持、實際投反對」的私人計畫與事後解釋。目前仍維持同一提案的公開立場與預定投票一致，尚未引入這個例外。

尚未實作：任意文字／語音的指控與引述解析、刻意說支持卻投反對的計畫、完整梅林身分機率、聯合世界推理、人格／難度。明確的結構化公開宣稱已能比較，普通聊天文字不會自動被解讀為這些欄位。

本批策略已調整：剩餘邪惡名額的起始評分、雙失敗協作、關鍵遠征與持劍者影響藏牌、翻劍前後結果比較，以及派西維爾固定候選人的舊查驗處理。任務歷史推理仍採保守啟發式；翻劍前所有人的原始牌尚未做完整聯合重建。

## 8. 修改與驗證

```sh
python tool/prepare_bot_dialogue.py
python tool/prepare_bot_dialogue.py --check
flutter analyze --no-pub
flutter test --no-pub
```

GitHub CI 加入資料庫一致性檢查。只改 JSON 或只改產物會失敗，必須同步產生；產物不要手動編輯。`test/bot_dialogue_test.dart` 檢查格式、引用與權限；`bot_social_dialogue_test.dart` 逐組驗證新增情境及錯誤指控／引述／時序等反例；`solo_session_test.dart` 包含 674 場完整擴充對局，並檢查已明說的立場與實際投票一致、指控與辯護確實出現、刺殺宣言對應實際目標。
